Keycloak Integration with AS2 Application

Date: 2026-07-05

Question 1: Using Application's User Database with Keycloak OAuth

Question: I want to utilize Keycloak to build OAuth server, but the underlying user data should use data in our application, is it possible?

Answer: Yes, it's absolutely possible! Keycloak supports User Federation and User Storage SPI which allows you to integrate your existing application's user database with Keycloak's OAuth/OIDC server.

Approach 1: User Storage SPI (Recommended for Full Control)

You implement a custom User Storage Provider that connects to your AS2 application's database:

  • Keycloak queries your webui_users table for authentication
  • You control password validation logic
  • User attributes (roles, permissions) come from your database
  • No data duplication - single source of truth

Pros:

  • Complete control over authentication logic
  • Single user database (your MySQL)
  • Real-time sync - changes in your app immediately reflected in Keycloak

Cons:

  • Requires Java development (implementing Keycloak SPI interfaces)
  • Need to deploy custom provider to Keycloak

Approach 2: Database Federation (Built-in)

Keycloak has a built-in LDAP/Database federation feature:

  • Point Keycloak directly to your MySQL database
  • Map your user table columns to Keycloak user attributes
  • Can be configured through Keycloak admin UI (no coding)

Pros:

  • No custom code needed
  • Easy to set up via UI

Cons:

  • Less flexible than custom SPI
  • Password hashing must be compatible

Approach 3: Hybrid Approach

  • Keep authentication in your app
  • Use Keycloak only for OAuth token generation
  • Your app validates credentials, then requests token from Keycloak

Recommendation: Given your setup (MySQL database with webui_users table), User Storage SPI is recommended if you want full OAuth/OIDC capabilities, or approach 3 if you want minimal changes to your existing authentication system.

Question 2: Keycloak Firewall Functionality

Question: Does Keycloak have firewall functionality?

Answer: No, Keycloak does not have built-in firewall functionality. It's an identity and access management (IAM) solution focused on authentication and authorization, not network security.

What Keycloak HAS:

  1. IP-based restrictions (limited):
    • Can configure allowed/denied IP ranges at the realm level
    • Useful for restricting admin console access
  2. Client Access Control:
    • Valid redirect URIs (whitelist of allowed callback URLs)
    • Web origins for CORS
    • Client authentication methods
  3. Brute Force Detection:
    • Temporary account lockout after failed login attempts
    • Configurable thresholds and lockout duration
  4. Session Management:
    • Timeout policies
    • Concurrent session limits
    • Session revocation

What Keycloak DOESN'T Have:

  • Network-level firewall (block/allow IPs, ports)
  • Rate limiting per IP (has account-level brute force detection only)
  • DDoS protection
  • WAF (Web Application Firewall) capabilities

Common Solutions for Firewall Functionality:

If you need firewall functionality for Keycloak, you typically use:

  1. Reverse Proxy (nginx, Apache, HAProxy):
    • IP whitelisting/blacklisting
    • Rate limiting
    • SSL/TLS termination
  2. Cloud WAF (if cloud-hosted):
    • Cloudflare
    • AWS WAF
    • Azure Application Gateway
  3. OS-level firewall:
    • iptables (Linux)
    • firewalld
    • UFW

Summary

  • Keycloak can integrate with your existing AS2 application's user database through User Storage SPI or Database Federation
  • Keycloak focuses on authentication/authorization, not network security
  • For firewall capabilities, use a reverse proxy or OS-level firewall in front of Keycloak
  • Consider your requirements (full OAuth vs minimal changes) when choosing the integration approach
